### Workflow
1. Client uploads file → `/upload` endpoint
2. Endpoint creates TaskStatus (PENDING), queues task, returns 202 + task_id
3. Celery worker receives task (state: STARTED)
4. Worker decodes base64 file data
5. Worker calls filebase_service.upload_to_filebase()
6. On success: Creates File record, updates user upload_count, updates TaskStatus (SUCCESS)
7. On failure: Updates TaskStatus (FAILURE or RETRY), retries with backoff
8. Audit log entry created for both success and failure

### Error Handling
- FilebaseError: Retry with exponential backoff (3 attempts)
- Other exceptions: Logged and stored in TaskStatus with error details

### Database Updates
- TaskStatus model tracks: task_id, user_id, task_type, state, result, timestamps
- File model: cid, user_id, original_filename, file_size, mime_type, pin_status
- User model: upload_count incremented
- AuditLog: Entry created with action="upload" and CID details
